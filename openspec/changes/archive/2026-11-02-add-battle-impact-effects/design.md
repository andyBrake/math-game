# Design

## 现状

- 答对时 `renderBattle` 给角色加 `act-mario` / `act-link`，给敌人加 `hit`，由 `hitShake` 播放 0.42 秒抖动。
- 敌人 HP 归零时，`session.answerLevel` 立即设置 `finished = true`，反馈区直接出现"查看结算"，敌人仍保持原样。
- 音效由 `js/audio.js` 的 `PATTERNS` 合成；目前没有爆炸音或噪声通道。
- 学期测验没有战斗舞台，答完直接进入报告。

## 白闪

- 在敌人容器内增加一层 `hit-flash`，用径向白色渐变覆盖敌人区域，不覆盖整个页面。
- 答对时渲染一次，CSS 动画约 100ms，动画结束随反馈重绘一起移除。
- 与现有 `hitShake`、闪电/星星特效并行；白闪层放在粒子层下方，避免遮挡商店特效。
- 只在 `mode === 'level'` 且 `lastAnswer.correct` 时触发；答错和学期测验不渲染。

## 爆炸

- 触发条件：`mode === 'level'`、`lastAnswer.correct`、`s.finished && s.won && s.hp <= 0`。
- 结构：`boom` 容器内放一个冲击波圆环和若干像素方块粒子；粒子通过 CSS 变量控制方向、距离和延迟，全部由 DOM/CSS 绘制。
- 规格：
  - 普通敌人：约 0.8 秒，12～16 个粒子，轻微震屏。
  - BOSS 形象：约 1.1 秒，20～24 个粒子，冲击波更大，震屏更强。
- 爆炸期间隐藏敌人图片，保留名字与空 HP 条，避免布局跳动。
- 爆炸只播一次；重玩时重新渲染并再次触发。
- 失败、答错、非致命命中不触发。

## 结算按钮节奏

- 反馈区先展示题干、解析和爆炸，再显示"查看结算"按钮。
- 普通敌人按钮延迟约 900ms，BOSS 约 1200ms；以爆炸实际时长为准，至少覆盖完整爆炸。
- 不自动跳转结算；按钮出现前不可点击。
- 定时器在重新渲染、返回地图或重新开始时清理，避免旧定时器影响下一关。

## 爆炸音

- 在 `js/audio.js` 新增 8-bit 爆炸音：低频锯齿/方波下坠 + 短噪声，普通约 0.6 秒，BOSS 更长更沉。
- 最后一击由战斗界面播放爆炸音，并让 `session` 不再播放普通答对/必杀音，避免叠音。
- 非致命答对仍使用现有 `correct` / `super` 音效。
- 所有声音继续受全局静音控制；不使用外部音频文件。

## 减少动态效果

- 通过 `matchMedia('(prefers-reduced-motion: reduce)')` 与 CSS 媒体查询双重判断。
- 开启时：不渲染白闪、不播放震屏；爆炸改为敌人约 0.2 秒淡出；按钮立即出现。
- 爆炸音仍播放，仍受静音开关控制；不额外增加设置项。

## 验证

- 普通敌人最后一击、BOSS 形象最后一击、非致命命中、答错、失败、重玩各走一遍。
- 检查按钮延迟、自动跳转、连击必杀、商店闪电/星星叠加。
- 检查静音、减少动态效果、375px 宽度、控制台 0 报错。
- 题目生成自检不受影响，`node tools/selfcheck.js` 仍通过。
